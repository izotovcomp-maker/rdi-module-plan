# Дизайн: красная полоса просрочки согласования + колонка 🔴

**Статус:** утверждён пользователем 2026-10-16.
**Ветка:** `красная-линия-при-задержке` (откат = не мержить / удалить ветку).
**ТЗ:** заказчик хочет видеть на Ганте красные полосы просрочки для незавершённых
модулей с датой согласования `UF_CRM_14_MOD_APPROVE` (поле `approveD`) ≤ сегодня,
и колонку с вычисленной задержкой в днях.

## Проблема

На Ганте не видно, какие незавершённые модули просрочили согласование и на сколько.
Заказчик ожидает визуальную индикацию прямо на полосах + числовую колонку.

## Условия красной зоны

Красная полоса рисуется, когда **одновременно**:

1. Модуль **не завершён** — стадия ∉ Завр/Анну (`STATUS_COMPLETED`, как в emphasis);
2. `approveD` заполнена и `approveD ≤ сегодня`;
3. `delay = сегодня − approveD ≥ 0`.

`delay` считается только от `approveD` (сегодня − approveD), без учёта расчётных
длительностей и `e3`.

## Правила отображения

| Ситуация | Красная полоса | Колонка 🔴 |
|---|---|---|
| delay > 0 | от `approveD` до правого края колонки «сегодня» | число `delay` |
| delay = 0 (approveD = сегодня) | не рисуется (нулевая ширина, рисовать негде) | `🔴 0` |
| approveD пустая | нет | `—` |
| approveD > сегодня | нет | `—` |
| модуль завершён (Завр/Анну) | нет | `—` |

- Полоса рисуется поверх сетки Ганта в общем `gantt-track` (та же пиксельная
  разкладка `leftPx/widthPx`), красным, полупрозрачная — не перекрывает сетку.
- Клиппинг слева (`approveD` левее начала шкалы) — от левого края, как у обычных
  полос (`layoutBars` уже умеет).
- Конец полосы — правый край колонки, содержащей «сегодня» (`todayIndex`), та же
  колонка, где вертикальная линия «сегодня».

## Новая колонка 🔴

- Добавляется **в конец** списка колонок (после «Р»), **sticky** при горизонтальном
  скролле — как остальные (механизм `--sticky-<key>`).
- Заголовок: `🔴`. В ячейках — число дней задержки или прочерк.
- Этапные строки — пустая ячейка; шапка группового ввода — без изменений.
- Сортировка по колонке: по `delay`, отсутствие — в конец (прочерк).

## Изменения по файлам

### www/js/gantt-logic.js (чистая логика, тесты в node)
- Новая функция `delayBar(m, todayIso, offsetIso, step)` →
  `{start: approveD, end: <правый край колонки сегодня>, days}` или `null`.
  - `null`: завершённый модуль (Завр/Анну), пустая `approveD`, `approveD > сегодня`.
  - `end = addDaysIso(offsetIso, (todayIdx + 1) * stepDays − 1)`, где
    `todayIdx` — индекс колонки «сегодня» (логика `todayIndex`, считается от
    `offsetIso`/`step`).
- Экспорт в `window.GanttLogic` + `module.exports`.

### www/js/app.js
- `barsFor()`: если `delayBar()` вернула объект — добавить в разметку красную
  полосу (класс `delay`, цвет в CSS), через существующий `layoutBars`.
- `HEAD_COLS`: + `{label: '🔴', key: 'delay', title: 'Задержка согласования — дней от даты согласования до сегодня'}`.
- `STICKY_W`: + 34px (как у «Р»); `STICKY_KEYS`: + `'delay'`.
- `cellValue` / `sortKey`: + key `'delay'` (число или `null` → прочерк).
- `renderBody`: ячейка `delay` в строках модулей (в этапных — пустая);
  `updateGantt` обновляет её вместе с `run`.

### www/css/app.css
- `.cell-delay { left: var(--sticky-delay); }`.
- `.gantt-bar.delay` — полупрозрачный красный (`rgba(213, 0, 0, .75)` или аналогичный).

### www/template.html — без изменений
### www/api/graph.php — без изменений (`approveD` уже отдаётся в `mapModule()`)

## Отвергнутые альтернативы

- **Только колонка без полосы** — заказчик явно просил полосу на Ганте.
- **Полоса без sticky-колонки** — число дней нужно заказчику рядом с данными.
- **Серверный расчёт delay** — не нужен: `approveD` уже приходит клиенту.
- **Фолбэк при пустой approveD на расчётную дату** — против ТЗ: пустая дата
  означает «согласование не ставилось», просрочки нет.
- **Трогать mock/** — макет исторический, не деплоится.

## Откат

Вся фича — коммит(ы) в ветке `красная-линия-при-задержке`; рабочий master не
меняется. Отказ заказчика от идеи = не мержить / удалить ветку. Бэк, `graph.php`,
данные портала и `mock/` не затрагиваются.
