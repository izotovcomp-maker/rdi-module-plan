# ПЕРЕДАЧА ПРОЕКТА — ЧИТАЙ ЭТО ПЕРВЫМ

> Этот файл — точка входа для **новой нейронки** (или человека), которая
> впервые открывает проект. Цель: за 5 минут понять **что это, где мы
> сейчас и куда идём** — без необходимости читать весь код.

---

## Как устроена память проекта

Весь контекст живёт в четырёх файлах. Читай их **в этом порядке**:

| # | Файл | Отвечает на вопрос | Как меняется |
|---|------|--------------------|--------------|
| 1 | [project-brief.md](./project-brief.md) | **Что** это за проект и **зачем** | Редко |
| 2 | [state.md](./state.md) | **Где мы сейчас** и **что делать дальше** | Постоянно — «живой снимок» |
| 3 | [changelog.md](./changelog.md) | **Что уже сделали** (по датам) | Только дописывается вниз |
| 4 | [decisions.md](./decisions.md) | **Почему** так, а не иначе | Только дописывается вниз |

Плюс [../AGENTS.md](../AGENTS.md) — инструкции по стеку, деплою и правилам работы.
Если есть `source/INDEX.md` — это описание входного контекста проекта (макеты, спецификации, материалы заказчика); прочитай и его.

---

## Быстрый старт для входящей нейронки

1. Прочитай 4 файла выше по порядку.
2. Глянь последние коммиты:
   ```bash
   git log --oneline -20
   ```
3. Проверь что прод живой — открой URL из раздела «Карта проекта» в `state.md`.
4. Возьми первый пункт из «Следующие шаги» в `state.md` — и продолжай.

**Дата снимка:** 2026-10-11
**В одном предложении:** Приложение «График модулей» (вкладка карточки смарт-процесса Сделки 1038) задеплоено и установлено на портале ooordi; таблица+Гант с редактированием сроков работают на макетной логике, первая загрузка реальных данных дала искажённую картинку — нужен Дебаг-вывод.
**Что работает прямо сейчас:** prod https://rub24.blackboxbegin.space/rdi-module-plan/ установлен на портале (токены в data/); вкладка CRM_DYNAMIC_1038_DETAIL_TAB привязана; api/graph.php отдаёт этапы/модули с dstart, runD/editD/waitD/approveD, статусами из воронки 1050; save — batch crm.item.update по 6 UF-полям.
**Что в процессе / недоделано:** график на реальных данных «не нормальный» — диагноз по Дебагу (format title/num-sname, UF_CRM_14_MOD_RUN/EDIT/WAIT/APPROVE, dstart); авто-бинд плейсментов в фазе 2 install-flow (сейчас кнопка «Плейсменты»); кэш crm.status.list (замечание ревью).
**Прод URL:** https://rub24.blackboxbegin.space/rdi-module-plan/
**Хостинг / slug:** prod, slug `rdi-module-plan`; SSH `ssh -i ~/.ssh/iagdeploy_ed25519 iagdeploy@rub24.blackboxbegin.space` (без sudo — Caddy правит человек с root; блок в Caddyfile добавлен 2026-10-11)
**Главные подводные камни:** dealId приходит в POST PLACEMENT_OPTIONS (JSON, ключ ID) — index.php прокидывает APP_DEAL_ID; статусы/цвета жёстко замаплены на STATUS_ID воронки C1050:20 (см. mock/mock-data.js, D-004); токены на сервере не читать/не печатать; при переустановке приложения — state.installFinished может остаться true (KB install-finish-per-user).
**Первое, что стоит сделать новому исполнителю:** получить от пользователя Дебаг-вывод (вкладка приложения → «Дебаг» → текст в чат) и скрин «что не так», сверить ответ api/graph.php с ожидаемыми полями и форматом title, починить рендер, затем прогнать живой цикл загрузка→правка→сохранение.
